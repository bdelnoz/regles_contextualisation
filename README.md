# regles_contextualisation

## Overview

`regles_contextualisation` is a documentation repository dedicated to contextualisation rules, scripting rules, rules-operation guidance, feature request standardization, AI working-information notes, and visual reference assets.

The repository is intended to keep reusable rule documents and operational documentation organized in a single public, version-controlled place.

## Repository Content

### Root Rule Documents

The root-level SOLO rule documents define reusable rule sets for different working contexts:

- contextualisation rules for general chat behavior;
- scripting rules for script, code, and technical documentation work;
- rules-operation guidance for maintaining SOLO rule files.

### Feature Request Standardization

The `Feature_requests_standardization/` directory contains reusable material for preparing structured feature requests, including:

- a feature request template;
- prompts for creating feature requests from existing conversations;
- prompts for generating short feature request titles;
- ready-to-send feature request examples.

### AI Working Information Documents

The `350_QUESTIONS_TO_GET_AI_WORKING_INFOS/` directory contains questionnaire and response documents about AI working behavior, context, memory, limits, tooling, formatting, and reliability.

### Visual Assets

The `VISUALS/` directory contains tracked visual references and image assets associated with the repository.

### Governance

`AGENTS.md` is the active repository governance file. It defines repository-specific operating rules for agents working in this repository.

`CLAUDE.md` is maintained as a compatibility pointer to `AGENTS.md`.

## How to Use This Repository

1. Start with this `README.md` for the repository overview.
2. Read `AGENTS.md` before making repository changes.
3. Use the root SOLO rule documents according to the task type:
   - contextualisation work;
   - scripting or code-generation work;
   - rule maintenance work.
4. Use the feature request standardization documents when preparing structured product or platform feature requests.
5. Use the AI working-information documents as reference material for questions about AI behavior, limits, context management, and reliability.
6. Use the tracked visual assets only when a task requires visual references from this repository.

## Documentation Language

Repository deliverables are written in English by default.

## Maintenance Notes

- Keep public documentation aligned with tracked repository content.
- Preserve governance files unless an explicit task requests a governance update.
- Do not invent undocumented behavior; describe only what is present and verifiable in the repository.

## Current Repository Nature

This repository is currently documentation-centered. No application runtime, build workflow, or automated test workflow is defined by the tracked repository content at this time.
